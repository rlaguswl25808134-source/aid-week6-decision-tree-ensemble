## 1. 05-1 결정 트리 (Decision Tree)

### 1.1 개념 정리
- **결정 트리**: 스무고개처럼 **예/아니오 질문**을 순서대로 던져 데이터를 나누고 최종 답(클래스/값)을 결정하는 알고리즘.
- **왜 이해하기 쉬운가**: 로지스틱 회귀는 계수(가중치)로 판단 근거가 표현되어 직관적 해석이 상대적으로 어렵지만, 결정 트리는 "**당도 ≤ 1.625인가? → 예/아니오**" 같은 **규칙**으로 표현되어 사람이 읽기 쉽다.
- **표준화(스케일링) 불필요**: 분할 기준이 값의 절대 크기가 아니라 **클래스 비율로 계산한 불순도**이기 때문에, `alcohol`, `sugar`, `pH`처럼 단위/범위가 달라도 표준화 여부와 결과가 같다. 원본 스케일을 쓰면 규칙 해석도 더 쉽다.

### 1.2 트리의 구성 요소
| 용어 | 뜻 | 쉬운 예시 |
|---|---|---|
| **노드(Node)** | 데이터를 나누는 질문(조건)이 담긴 상자 | "당도 ≤ 1.625?" |
| **루트 노드(Root)** | 맨 위 시작 노드, 전체 데이터가 들어 있음 | 첫 번째 질문 |
| **리프 노드(Leaf)** | 더 이상 나누지 않는 끝 노드, 여기서 예측 결정 | "화이트 와인으로 예측" |
| **가지(Branch)** | 질문의 결과(예/아니오)를 따라 내려가는 경로 | 조건 만족/불만족 경로 |
| **깊이(Depth)** | 루트에서 특정 노드까지의 단계 수 | 질문을 몇 번 거쳤는지 |

- `plot_tree()` 노드에 보통 담기는 정보: **테스트 조건**, **불순도(gini/entropy)**, **샘플 수(samples)**, **클래스별 샘플 수(value)**.

### 1.3 불순도(Impurity): 질문을 고르는 기준
노드 안의 데이터가 얼마나 섞여 있는지를 수치화한 것. 트리는 **불순도를 가장 많이 줄이는 질문**을 선택한다.

#### 지니 불순도 (Gini, 기본값)
- **공식**: \( Gini = 1 - \sum (클래스\ 비율)^2 \) (이진 분류: \(1 - (p_{음성}^2 + p_{양성}^2)\))
- **해석**:
  - 한 클래스만 있음(완전 순수) → **0** (가장 좋음)
  - 반반 섞임(50:50) → **0.5** (이진 분류에서 최악)
- **쉬운 예시 (피자)**: 피자 100조각이 한 사람 것(100:0)이면 헷갈릴 게 없음(불순도 0). 두 사람이 50:50으로 나누면 집을 때마다 헷갈림(불순도 0.5). 결정 트리는 "덜 헷갈리는(순수한)" 쪽으로 나누는 질문을 고른다.
- **와인 루트 노드 예**: 레드 1258, 화이트 3939, 총 5197 → \(1 - ((1258/5197)^2 + (3939/5197)^2) \approx 0.367\)

#### 엔트로피 불순도 (Entropy)
- **공식**: \( Entropy = -\sum (클래스\ 비율 \times \log_2(클래스\ 비율)) \)
- `criterion='entropy'`로 사용. 의미는 지니와 유사(섞일수록 큼, 순수할수록 0)하며 보통 결과 차이는 크지 않음.

### 1.4 정보 이득(Information Gain)
- **의미**: 부모 노드가 자식 노드로 나뉘면서 불순도가 얼마나 줄었는지.
- **공식**: \( 정보\ 이득 = 부모\ 불순도 - (왼쪽\ 샘플비율 \times 왼쪽\ 불순도) - (오른쪽\ 샘플비율 \times 오른쪽\ 불순도) \)
- **선택 원리**: 가능한 특성과 기준값 조합 중 **정보 이득이 최대**가 되는 분할을 선택.
- **쉬운 예시**: 반 전체를 두 모둠으로 나눌 때, "안경 착용 여부"보다 "수학 점수 80점 기준"으로 나누는 게 모둠별 성향이 더 뚜렷해진다면 후자의 정보 이득이 더 크다.

### 1.5 과대적합과 가지치기(Pruning)
- **과대적합 징후**: 훈련 점수는 매우 높지만(예: 0.997) 테스트 점수는 낮음(예: 0.859) → 훈련 데이터의 세세한 잡음까지 외운 상태.
- **가지치기**: 트리가 무한정 자라지 않도록 제한해 일반화 성능을 높임.
  - 대표 방법: `max_depth`(최대 깊이) 제한. 예) `max_depth=3` → 훈련 점수는 내려가지만 훈련/테스트 격차가 줄고, 트리가 단순해져 해석이 쉬워짐.
  - 그 외: `min_samples_split`, `min_samples_leaf`, `min_impurity_decrease` 등.

### 1.6 특성 중요도(Feature Importance)
- `feature_importances_`: 각 특성이 **불순도 감소에 기여한 정도**. 값의 합은 1.
- 와인 예시: `[alcohol, sugar, pH] = [0.123, 0.869, 0.008]` → **당도(sugar)**가 분류에 가장 큰 영향을 줌.
- **활용**: 중요한 변수 파악, 불필요한 특성 후보 확인(특성 선택 참고), 모델 해석/보고.

### 1.7 실제로는 어디에, 무엇을 판별/예측하는 데 쓰이나?
| 분야 | 입력(특성) 예시 | 판별/예측 대상 | 왜 결정 트리를 쓰나 |
|---|---|---|---|
| 식품/품질 | 당도, 산도, 알코올 도수 등 | 와인 종류/등급 분류 | 규칙이 명확해 품질 기준 설명 가능 |
| 의료(보조) | 검사 수치, 증상 유무 | 질환 위험군 분류, 검사 필요 여부 | 판단 경로를 설명하기 쉬움 |
| 금융 | 소득, 거래 패턴, 연체 이력 | 대출 승인/거절, 이상거래 여부 | 의사결정 근거(규칙) 제시 용이 |
| 마케팅/CRM | 이용 횟수, 구매 금액, 접속 패턴 | 고객 이탈(churn) 여부 | 이탈 조건을 세그먼트 규칙으로 파악 |
| 운영/제조 | 센서 값, 공정 조건 | 불량/정상 판별, 고장 징후 | 현장 규칙으로 변환하기 쉬움 |

> 주의: 단일 결정 트리는 데이터 변화에 민감하고 과대적합되기 쉬워, 실무에서는 뒤의 **앙상블(05-3)**로 성능과 안정성을 높이는 경우가 많다.

### 1.8 (참고) 이번 주 사용된 주요 코드
- 데이터/분할: `pd.read_csv`, `train_test_split(..., test_size=0.2, random_state=42)`
- 모델 학습/평가: `DecisionTreeClassifier(random_state=42)`, `.fit()`, `.score()`
- 시각화: `plot_tree(dt, max_depth=..., filled=True, feature_names=[...])`
- 규제/해석: `max_depth`, `criterion='entropy'`, `.feature_importances_`

## 2. 05-2 교차 검증과 그리드 서치

### 2.1 검증 세트가 필요한 이유
- **문제**: `max_depth`, `min_samples_split` 등을 바꿔가며 **테스트 세트로** 성능을 비교하면, 모델이 테스트 세트에 맞춰 선택되어 "최종 평가" 의미가 오염됨.
- **원칙**: **테스트 세트는 마지막에 딱 한 번**만 사용.
- **해결**: 훈련 세트를 다시 나눠 **검증 세트(validation set)**를 만들어 하이퍼파라미터 선택에 사용.

| 구분 | 역할 |
|---|---|
| 훈련(sub/train) 세트 | 모델 학습 |
| 검증(validation) 세트 | 하이퍼파라미터 비교·선택 |
| 테스트(test) 세트 | 최종 성능 확인(마지막 1회) |

- 예: 전체 → (훈련 80% / 테스트 20%), 훈련 → (서브 훈련 / 검증) 추가 분할

### 2.2 교차 검증(Cross Validation)
- **개념**: 훈련 세트를 **k개의 폴드(fold)**로 나누고, 각 폴드를 한 번씩 검증 세트로 쓰며 k번 평가한 뒤 평균을 사용.
- **장점**: 한 번만 나눌 때보다 평가가 안정적이고, 검증용 데이터를 따로 크게 떼어 놓는 낭비를 줄임.
- **쉬운 예시**: 모의고사를 하루 한 번만 보면 컨디션에 따라 점수가 흔들리지만, 여러 번 나눠 보면 실력을 더 안정적으로 가늠할 수 있음. 교차 검증은 "**여러 번 나눠 보는 모의고사**".
- **주의**: `cross_validate` 결과의 `test_score` 키는 **검증 폴드 점수**를 의미(최종 테스트 세트 점수 아님).
- **분류 데이터**: 기본적으로 클래스 비율을 유지하는 **StratifiedKFold**(계층적 k-폴드)를 사용. `shuffle=True`, `random_state`로 분할 재현 가능.

### 2.3 하이퍼파라미터 튜닝
| 구분 | 설명 | 예시 |
|---|---|---|
| **모델 파라미터** | 학습 과정에서 데이터로부터 모델이 스스로 찾는 값 | 트리의 분할 규칙/구조, 선형모델의 계수 등 |
| **하이퍼파라미터** | 사용자가 학습 전에 지정하는 값 | `max_depth`, `min_samples_split`, `min_impurity_decrease`, `n_estimators`, `learning_rate` 등 |

- **중요**: 하이퍼파라미터는 서로 영향을 줌. `max_depth`의 최적값은 `min_samples_split`에 따라 달라질 수 있으므로 **여러 매개변수를 함께** 탐색해야 함.

### 2.4 그리드 서치 (GridSearchCV)
- **개념**: 탐색할 하이퍼파라미터 값의 **격자(모든 조합)**를 지정하면, 각 조합에 대해 **교차 검증**을 수행해 최적 조합을 찾음.
- **장점**: 체계적이고 재현 가능, 최적 조합/결과를 객체에 저장.
- **비용**: 조합 수 × 폴드 수만큼 모델을 학습하므로 탐색 공간이 크면 시간이 많이 듦. (예: 9×15×10=1350 조합, 5-폴드 → 6750번 학습)
- **주요 요소**:
  - `param_grid`: 탐색할 값 목록
  - `best_params_`: 최고 평균 검증 점수의 매개변수 조합
  - `best_estimator_`: 최적 조합으로 **전체 훈련 세트**에 다시 학습된 모델
  - `cv_results_['mean_test_score']`: 각 조합의 평균 검증 점수
  - `n_jobs=-1`: 가능한 CPU 코어를 병렬 사용해 속도 향상

### 2.5 랜덤 서치 (RandomizedSearchCV)
- **개념**: 값 목록 대신 **확률 분포**에서 하이퍼파라미터를 무작위로 샘플링해 탐색.
- **언제 유용한가**: 탐색 범위가 넓거나 연속적인 값일 때, 제한된 횟수(`n_iter`)로도 유망한 영역을 효율적으로 탐색 가능.
- **분포 예시**: `randint(a, b)`(정수 범위), `uniform(loc, scale)`(실수 범위).
- **비교**: 그리드 서치가 "모든 칸을 꼼꼼히"라면, 랜덤 서치는 "넓은 지도에서 좋은 지점을 빠르게 찍어 보는" 방식.

### 2.6 실제로는 어디에 쓰이나?
- **모델 선택의 신뢰도 확보**: 의료/금융/품질 판별처럼 오판 비용이 큰 문제에서, 한 번의 분할 결과가 아닌 교차 검증 평균으로 성능 판단.
- **하이퍼파라미터 자동 튜닝**: 스팸, 이탈, 불량 판별 등 분류기의 `max_depth`, 트리 개수, 학습률 등을 데이터에 맞게 찾을 때.
- **과대적합 점검**: 훈련 점수 vs 검증 점수 비교로 모델 복잡도 조절.
- **실무 팁**: 넓은 범위는 랜덤 서치로 후보를 좁히고, 좁은 범위는 그리드 서치로 정밀 탐색하는 전략을 자주 사용.

### 2.7 (참고) 이번 주 사용된 주요 코드
- 검증 분할: `train_test_split(train_input, train_target, test_size=0.2, ...)`
- 교차 검증: `cross_validate(dt, train_input, train_target)`, `StratifiedKFold(n_splits=10, shuffle=True, ...)`
- 그리드 서치: `GridSearchCV(DecisionTreeClassifier(...), params, n_jobs=-1)`, `.fit()`, `best_params_`, `best_estimator_`, `cv_results_`
- 랜덤 서치: `randint`, `uniform`, `RandomizedSearchCV(..., n_iter=100, n_jobs=-1, random_state=42)`

## 3. 05-3 트리의 앙상블 (Ensemble Learning)

### 3.1 배경: 정형 데이터와 비정형 데이터
| 구분 | 형태 | 예시 | 잘 맞는 모델 경향 |
|---|---|---|---|
| **정형 데이터(Structured)** | 행/열 구조로 정리된 표 형태 | CSV, DB, 엑셀(수치·범주 컬럼) | 결정 트리 기반 모델, **앙상블(랜덤 포레스트·부스팅 등)**이 강력한 성능을 보이는 경우가 많음 |
| **비정형 데이터(Unstructured)** | 고정된 표 구조로 다루기 어려움 | 텍스트, 이미지, 음성 | 신경망/딥러닝 계열이 주로 활용됨 |

- 와인 데이터(알코올 도수, 당도, pH → 클래스)는 **정형 데이터**이며, 앙상블 학습이 좋은 성과를 내기 쉬운 영역이다.

### 3.2 앙상블 학습이란?
- **정의**: 여러 개의 모델(주로 결정 트리)을 함께 학습·결합해 **하나의 더 좋은 예측**을 만드는 방법.
- **핵심 직관**: "나무 한 그루보다 숲을 본다". 한 그루의 트리는 불안정하거나 과대적합되기 쉽지만, 여러 트리의 의견을 모으면 오류가 상쇄되어 **일반화 성능과 안정성**이 높아지는 경우가 많다.
- **결합 방식(일반적)**:
  - **분류**: 여러 트리의 예측/확률을 모아 다수결 또는 평균 확률로 최종 클래스 결정
  - **회귀**: 여러 트리의 예측값 평균
- **대표 방식**: 
  - **배깅(Bagging)** 계열: 독립적으로 만든 여러 모델을 평균/투표 (예: 랜덤 포레스트, 엑스트라 트리)
  - **부스팅(Boosting)** 계열: 이전 모델의 오차를 보완하며 순차적으로 모델 추가 (예: 그레이디언트 부스팅, 히스토그램 기반 부스팅)

### 3.3 랜덤 포레스트 (Random Forest)
> 앙상블의 대표 주자. "랜덤하게 만든 결정 트리들의 숲"

#### 핵심 개념
- **여러 결정 트리를 학습**한 뒤 결과를 종합 (기본적으로 100개 트리).
- **랜덤성 1) 부트스트랩 샘플(Bootstrap Sampling)**: 원본 훈련 세트에서 **중복을 허용**해 같은 크기의 샘플을 뽑아 각 트리의 학습 데이터로 사용. 어떤 샘플은 여러 번 뽑히고, 어떤 샘플은 아예 뽑히지 않을 수 있음.
- **랜덤성 2) 특성 부분 선택**: 각 노드를 분할할 때 전체 특성 중 일부를 무작위로 고르고 그 안에서 최선의 분할 탐색.
  - 분류: 기본적으로 특성 수의 제곱근만큼 선택
  - 회귀: 보통 전체 특성 사용
- **예측 결합**: 분류는 트리들의 클래스별 확률을 평균해 가장 높은 클래스를 선택, 회귀는 예측값 평균.

#### OOB(Out-of-Bag) 점수
- 부트스트랩 과정에서 각 트리의 학습에 **포함되지 않은 샘플**이 생김(OOB 샘플).
- 이 샘플로 해당 트리를 평가해 평균 낸 점수가 **OOB score** (`oob_score=True`).
- 별도의 검증 세트/교차 검증을 보완하는 지표로 활용 가능해, 훈련 데이터를 더 활용할 수 있음.

#### 특성 중요도
- 숲을 구성하는 개별 트리들의 중요도를 종합. 단일 트리보다 한 특성에 과도하게 집중하는 경향을 줄여 **여러 특성의 기여를 볼 기회**가 생김.

#### 장단점과 쓰임
- **장점**: 기본 설정에서도 준수한 성능, 과대적합 완화, 병렬 학습 용이(`n_jobs=-1`), 분류/회귀 모두 가능.
- **단점**: 단일 트리보다 해석이 어려움, 많은 트리로 메모리/예측 시간 증가 가능.
- **쓰임**: 정형 데이터 분류/회귀의 강력한 베이스라인. 예) 고객 이탈 판별, 대출 부도 위험 분류, 질병 위험도 분류, 수요/가격 예측.

#### (참고) 주요 코드
- `RandomForestClassifier(n_jobs=-1, random_state=42)`
- `cross_validate(..., return_train_score=True, n_jobs=-1)`
- `oob_score=True` 후 `rf.oob_score_`, `rf.feature_importances_`

### 3.4 엑스트라 트리 (Extra Trees, Extremely Randomized Trees)
> 랜덤 포레스트와 비슷하지만 **더 무작위**한 트리 앙상블

#### 랜덤 포레스트와의 차이
| 항목 | 랜덤 포레스트 | 엑스트라 트리 |
|---|---|---|
| 학습 샘플 | 부트스트랩 샘플(중복 허용) | **전체 훈련 세트 사용**(기본) |
| 노드 분할 | 후보 특성 중 **최선의 분할** 탐색 | 후보 중 **무작위로 분할** 선택 |
| 무작위성 | 있음 | 더 큼 |
| 속도 | 보통 | 분할 탐색 비용이 줄어 **빠른 편** |
| 트리 수 | 기본 100 | 무작위성 보완 위해 **더 많은 트리**가 유리할 수 있음 |

- **직관**: 한 트리의 분할이 다소 엉성해져도, 많은 트리를 앙상블하면 과대적합을 줄이고 성능을 확보할 수 있음.
- **회귀 버전**: `ExtraTreesRegressor`.
- **쓰임**: 랜덤 포레스트와 유사한 정형 데이터 분류/회귀. 빠른 학습/실험이 필요하거나 노이즈에 강한 모델을 원할 때 시도.

#### (참고) 주요 코드
- `ExtraTreesClassifier(n_jobs=-1, random_state=42)`, 학습 후 `feature_importances_`

### 3.5 그레이디언트 부스팅 (Gradient Boosting)
> **이전 트리의 오차를 보완**하며 순차적으로 트리를 쌓는 앙상블

#### 핵심 개념
- **순차적(Sequential) 학습**: 새 트리가 **이전까지 앙상블의 오차(손실)**를 줄이는 방향으로 추가됨.
- **얕은 트리 사용**: 기본적으로 깊이가 얕은 결정 트리(예: `max_depth=3`)를 여러 개(기본 100개) 사용. 약한 학습기를 조금씩 보완해 누적.
- **경사 하강법과의 연결**: 손실 함수를 줄이는 방향으로 모델을 업데이트. 분류에서는 로지스틱 손실, 회귀에서는 평균 제곱 오차(MSE) 등을 사용. 트리를 추가해 손실 함수의 "낮은 곳"으로 이동한다고 볼 수 있음.
- **학습률(`learning_rate`)**: 각 트리가 전체 앙상블에 기여하는 크기를 조절. 작게 하면 천천히 학습(보통 더 많은 트리 필요), 크게 하면 빠르지만 과적합/불안정 위험이 커질 수 있음.

#### 주요 하이퍼파라미터 감각
- `n_estimators`: 부스팅 단계(추가할 트리) 수. 늘리면 표현력↑, 과적합/시간↑ 가능(학습률과 함께 조절).
- `learning_rate`: 기본 0.1. 성능 튜닝 시 `n_estimators`와 함께 조정.
- `max_depth`: 개별 트리 깊이(기본 3). 얕을수록 보수적.
- `subsample`: 각 단계에 사용할 훈련 샘플 비율(기본 1.0). 1 미만이면 일부만 랜덤 사용해 확률적 경사 하강/미니배치와 유사한 효과.

#### 장단점과 쓰임
- **장점**: 정형 데이터에서 높은 예측 성능을 내는 경우가 많음, 얕은 트리 기반으로 과대적합에 비교적 강함.
- **단점**: 트리를 **순서대로** 추가해야 하므로 기본 구현은 병렬화가 어렵고(사이킷런 `GradientBoostingClassifier`는 `n_jobs` 없음) 랜덤 포레스트보다 느릴 수 있음, 튜닝 민감도 존재.
- **쓰임**: 성능이 중요한 정형 데이터 분류/회귀. 예) 신용 평가, 사기 탐지, 클릭/전환 예측, 위험 점수화.

#### (참고) 주요 코드
- `GradientBoostingClassifier(random_state=42)`
- 튜닝 예: `GradientBoostingClassifier(n_estimators=500, learning_rate=0.2, random_state=42)`

### 3.6 히스토그램 기반 그레이디언트 부스팅 (Histogram-based Gradient Boosting)
> 그레이디언트 부스팅을 **더 빠르고 실용적으로** 만든 방식

#### 핵심 개념
- **입력 특성의 구간화(Binning)**: 연속형 특성을 **256개 구간(빈)**으로 나눠 다룸. 분할 후보가 제한되어 **최적 분할 탐색이 매우 빠름**.
- **누락값(Missing Value) 처리**: 누락값을 위한 구간을 활용할 수 있어, 입력에 결측이 있어도 **별도 전처리 없이** 학습 가능한 경우가 많음(구현 특성).
- **반복 횟수 파라미터**: 사이킷런 구현에서는 트리 개수 개념으로 `n_estimators` 대신 **`max_iter`**(부스팅 반복 횟수)를 사용.
- **특성 중요도 확인**: `permutation_importance`로 특성을 무작위로 섞었을 때 성능 변화량을 측정해 중요도를 계산(훈련/테스트 세트 모두 적용 가능, 다양한 모델에 사용 가능).

#### 관련 라이브러리
- **사이킷런**: `HistGradientBoostingClassifier` / `HistGradientBoostingRegressor`
  - (환경에 따라) 구버전에서는 `from sklearn.experimental import enable_hist_gradient_boosting` 후 사용, 최신 버전에서는 불필요할 수 있음.
- **XGBoost**: `XGBClassifier(tree_method='hist', ...)` 등으로 히스토그램 기반 방식 사용 가능.
- **LightGBM**: 마이크로소프트의 고성능 구현, 속도와 최신 기법으로 널리 사용.

#### 장단점과 쓰임
- **장점**: 대체로 **빠르고 높은 성능**, 결측값 처리 편의, 정형 데이터 대회/실무에서 매우 인기.
- **단점**: 모델 해석 난이도(앙상블 공통), 데이터/문제에 따라 튜닝 필요.
- **쓰임**: 대용량·고차원 정형 데이터의 분류/회귀 전반(금융 리스크, 마케팅 반응 예측, 제조 품질 판별 등).

#### (참고) 주요 코드
- `HistGradientBoostingClassifier(random_state=42)`, `cross_validate`, `.score`
- 중요도: `permutation_importance(model, X, y, n_repeats=10, random_state=42, n_jobs=-1)` → `result.importances_mean`
- 외부 라이브러리: `XGBClassifier(tree_method='hist', random_state=42)`, `LGBMClassifier(random_state=42)`

### 3.7 앙상블 모델 비교 요약
| 모델 | 학습 방식 | 랜덤성/특징 | 속도·병렬성 | 대표 강점 |
|---|---|---|---|---|
| **Random Forest** | 배깅(독립 트리) | 부트스트랩 + 노드별 특성 부분 선택 | 병렬화 용이 | 튼튼한 기본 모델, OOB 활용 |
| **Extra Trees** | 배깅 계열(독립 트리) | 전체 샘플 + **무작위 분할** | 분할 탐색이 단순해 빠를 수 있음 | 속도, 강한 무작위성 |
| **Gradient Boosting** | 부스팅(순차적 보완) | 이전 오차를 줄이는 얕은 트리 추가 | 순차 학습으로 느릴 수 있음 | 높은 예측 성능 |
| **HistGradientBoosting** | 부스팅(히스토그램 기반) | 256-bin 분할, 결측값 처리 편의 | GB 대비 매우 빠름 | 속도·성능·결측 처리 균형 |

### 3.8 실제로 무엇을 판별/예측하는 데 쓰이나? (예시)
| 과제 유형 | 예시 질문(판별/예측) | 적합한 이유 |
|---|---|---|
| 이진/다중 분류 | 이 고객이 이탈할까? 이 거래가 사기인가? 이 와인이 레드/화이트인가? | 정형 특성의 비선형 관계·상호작용 포착에 강함 |
| 회귀 | 내일 수요는 얼마인가? 주택 가격은 얼마인가? | 여러 트리의 평균/보완으로 안정적 수치 예측 |
| 위험 점수화 | 부도/사고/불량 발생 확률은? | 확률/점수 출력 및 중요 특성 분석에 활용 가능 |
| 특성 영향 분석 | 어떤 변수가 결과에 가장 큰 영향을 주나? | `feature_importances_`, 순열 중요도로 해석 단서 제공 |

> 실무 흐름 예: **데이터 분할 → 교차 검증으로 기준 성능 확인 → (랜덤 포레스트 등 베이스라인) → 그리드/랜덤 서치로 튜닝 → 최종 테스트 1회 평가**.

## 4. 6주차 스터디 요약
- **결정 트리**: 스무고개식 규칙 모델. **불순도(지니/엔트로피)**를 줄이는 분할을 선택하고, **정보 이득**이 큰 질문을 채택. 해석과 특성 중요도 분석이 쉽고 **표준화가 필요 없음**. 단, 깊이 제한 없는 트리는 **과대적합**되기 쉬움.
- **교차 검증/튜닝**: 테스트 세트를 보호하기 위해 **검증 세트/교차 검증**으로 평가하고, **GridSearchCV/RandomizedSearchCV**로 하이퍼파라미터를 체계적으로 탐색.
- **앙상블**: 여러 트리를 결합해 단일 트리보다 안정적이고 높은 성능을 노림. **랜덤 포레스트/엑스트라 트리**는 병렬적 다양성(배깅 계열), **그레이디언트 부스팅/히스토그램 기반 부스팅**은 순차적 오차 보완(부스팅 계열)이라는 차이가 핵심.
- **정형 데이터의 분류·회귀 문제**에서 앙상블 트리 모델은 실무적으로 매우 강력한 선택지이며, 최종 목적은 "잘 맞추는 것"뿐 아니라 **일반화 성능을 믿을 수 있게 확보**하는 데 있음.
